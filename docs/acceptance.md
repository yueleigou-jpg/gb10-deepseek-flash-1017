# 四节点集群公开验收记录

测试环境为四台 FusionXpark GB10（每台 128 GB 统一内存、NVIDIA 驱动 580.178.04）。节点编号仅表示通信与计算顺序。

### 集群与环网

四个 GPU rank 同时运行，逐元素检查 AllReduce 和 AllGather 结果。随后同一个服务通过真实生成请求及并发测试。四条物理链路均协商为 200 Gb/s。主机内存 RoCE v2 写入使用 ib_write_bw，单次消息 1 MiB，持续 5 秒，同一线缆的两个 PCI 通道同时测量并合计。每个方向单独测试。

| 相邻节点 A / B | A 到 B（Gb/s） | B 到 A（Gb/s） |
|---|---:|---:|
| 1 / 4 | 185.14 | 185.18 |
| 4 / 3 | 185.18 | 185.06 |
| 3 / 2 | 185.06 | 185.17 |
| 2 / 1 | 185.18 | 185.14 |

### 模型与接口

四台均校验固定版本的 83 个文件，含 48 个权重分片，共 510,311,045,295 字节。配置记录 quant_method 为 fp8、expert_dtype 为 fp4。服务日志显示专家模块 W4A8、FP8 输出投影及 FP8 草稿模块均已启用，排除了 Q2 权重。

在同一管理局域网的客户端，对聊天接口发送相同的算术请求。匿名和错误密钥分别收到 HTTP 401，正确密钥收到 HTTP 200 并返回 42。Open WebUI 登录后完成中文问答。主节点上的 DSH 0.1.2-rc.1 通过本地 API 使用该模型，在网页会话中完成了一次实际文件读取工具调用，正确返回文件中的随机码，界面显示约 3 秒。

### 速度与质量

三轮交替测试和两轮独立并发扫描使用同一部署配置。单路取稳定区间，八路取全组实际输出数除以整组耗时。

| 轮次 | 单路稳定速度（token/s） | 八路合计（token/s） |
|---|---:|---:|
| 交替 1 | 94.24 | 279.20 |
| 交替 2 | 87.87 | 291.47 |
| 交替 3 | 88.73 | 301.46 |
| 完整套件 | 88.55 | 281.87 |
| 作者原始脚本 | 90.27 | 290.02 |
| 五次中位数 | **88.73** | **290.02** |

原帖单轮参考值为 90.4 和 296.3 token/s。两项现场速度各有一轮超过参考值。最快八路请求输出 25,677 token，耗时 85.174 秒，首 token 等待中位数为 0.542 秒。独立运行作者原始脚本时，两路合计为 145.24，四路为 202.89 token/s。

1,001,299 token 冷输入返回一个输出 token，用时 268.14 秒。957,029 token 长文本检索首次和重复请求均正确，分别耗时 233.68 和 3.27 秒。75 道质量测试通过 72 道，逐题速度中位数 72.01 token/s。结构化 JSON 输出、工具调用及结果回传、原生图像理解均通过。
